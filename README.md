## Задание 1 (3)

- `const auto Pi = std::acos(0) * 2;` — обычный константный объект. Значение нельзя менять через `Pi`, но это не гарантирует вычисление на этапе компиляции.
- `constexpr auto Pi = std::acos(0) * 2;` — требует, чтобы выражение было допустимым константным выражением. В стандартных версиях C++, где `std::acos` не является `constexpr`, такой вариант не компилируется.
- `const auto Pi = std::acos(x) * 2;` — компилируется, но значение зависит от переменной `x`. Это не константа этапа трансляции.
- `constexpr auto Pi = std::acos(x) * 2;` — не компилируется: `x` — обычная переменная, а выражение с ней не является константным выражением. Даже если библиотека поддерживает `constexpr` для `acos`, это не делает переменную `x` константой времени компиляции.

## Задание 3 (2)

Результат программы — **18**.

Во внешнем цикле создаётся `i`, который последовательно принимает значения `0...3`. Внутренний цикл объявляет собственную переменную `i`, она скрывает внешнюю только внутри внутреннего цикла и принимает значения `0...2`. Поэтому за один проход внутренний цикл прибавляет `0 + 1 + 2 = 3`. За четыре прохода это `3 * 4 = 12`.

После завершения внутреннего цикла снова доступна внешняя `i`. Команда `s += i` добавляет `0 + 1 + 2 + 3 = 6`. Итог: `12 + 6 = 18`. Область видимости внутренней переменной заканчивается вместе с внутренним циклом.

## Задание 4 (2)

Результат программы — **20**.

В Python цикл не создаёт отдельную область видимости для переменной, объявленной в заголовке `for`. Внутренний цикл перезаписывает `i` значениями `0...2`. После него `i` остаётся равной `2`, поэтому команда `s += i` каждый раз добавляет `2`.

За каждый из четырёх проходов прибавляется `0 + 1 + 2 + 2 = 5`. Всего `5 * 4 = 20`. При этом внешний цикл продолжает четыре итерации: его итератор хранит последовательность `range(4)` независимо от текущего значения имени `i`.

в C++ переменная внутреннего цикла имеет собственную область видимости и не изменяет внешнюю `i`. В Python имя `i` после внутреннего цикла остаётся связанным с последним значением — `2`.

## Задание 7 (2)

При первом присваивании создаётся строковый объект `'Hello world'`, а имя `a` ссылается на него. После `b = a` оба имени ссылаются на один объект, поэтому первые два вызова `id` показывают одинаковое значение.

Строки в Python неизменяемы. Выражение `a += ' and goodbye'` создаёт новую строку с объединённым содержимым и связывает имя `a` с новым объектом. Имя `b` по-прежнему указывает на старую строку `'Hello world'`. Поэтому последние две строки вывода показывают разное содержимое и разные значения `id`.

`id()` возвращает идентификатор объекта, который уникален среди одновременно существующих объектов.

## Задание 8 (2)

```Python
a = "Hello world"
```

В обоих случаях переменные содержат одинаковую строку. Присваивание `b = a` связывает `b` с тем же объектом, что и `a`. Выражение `a[:]` создаёт срез всей строки, однако Python может вернуть тот же объект. Поэтому в CPython `a is c` также может быть `True`. ## Задание 9 (3)

В Python имена переменных можно создать динамически через словарь `globals()`. Каждой переменной присваивается отдельное целое значение от 1 до 2600.

```python
letters = 'abcdefghijklmnopqrstuvwxyz'

for letter_index, letter in enumerate(letters):
    for number in range(100):
        name = f'{letter}{number}'
        globals()[name] = letter_index * 100 + number + 1

# Проверка границ и количества созданных имён
print(a0)    # 1
print(a99)   # 100
print(b0)    # 101
print(z99)   # 2600

created = [
    name
    for letter in letters
    for name in (f'{letter}{number}' for number in range(100))
]
print(len(created))  # 2600
print(len({globals()[name] for name in created}))  # 2600
```

# Дополнительные задания

## Задание 1 (3)

Да, обмен `a, b = b, a` работает. Сначала Python вычисляет правую часть — получает ссылки на объекты, на которые указывают `b` и `a`. Затем выполняет присваивание этим ссылкам именам слева. Поэтому промежуточная переменная не нужна и значения не теряются.

Для списков копирования элементов не происходит: перемещаются только ссылки на объекты. Время обмена не зависит от длины списков — это операция постоянной сложности.

```python
a = [1, 2, 3]
b = ['x', 'y']

a, b = b, a

print(a)  # ['x', 'y']
print(b)  # [1, 2, 3]
```

## Задание 2 (3)

В интерактивной среде выражения `id(100) == id(100)` и `id(1000) == id(1000)` могут оба вернуть `True`, но это не гарантировано как универсальное правило языка. В CPython небольшие целые числа часто заранее сохранены и повторно используются. Для других целых чисел результат зависит от реализации и от того, когда создаются временные объекты: первый временный объект может быть уничтожен до создания второго, и его идентификатор может быть повторно использован.

## Задание 3 (4)

В обычном интерактивном сеансе IDLE пользовательские переменные находятся в глобальном пространстве имён. Функция ниже суммирует значения целочисленных переменных, исключая `bool`, поскольку в Python `bool` является подклассом `int`, но логические значения обычно не считают целыми данными для этой задачи.

```python
def sumint():
    return sum(
        value
        for name, value in globals().items()
        if isinstance(value, int)
        and not isinstance(value, bool)
    )
```

Пример в IDLE:

```python
a = 10
b = 1.5
c = 15
d = 'hello'
e = True

sumint() # 25
```

```cpp
#include <string>
#include <cstdint>

template <typename T>
void show(const char* name, T& value) {
    auto address = reinterpret_cast<std::uintptr_t>(&value);
    std::cout << name

              << ", sizeof=" << sizeof(value) << '\n';
```

### Пример 3. Размер и адрес `std::string`

```cpp
#include <iostream>
#include <string>
#include <cstdint>

int main() {
    std::string a;
    std::string b;

    auto address_a = reinterpret_cast<std::uintptr_t>(&a);
    auto address_b = reinterpret_cast<std::uintptr_t>(&b);

    std::cout << "empty: sizeof(a)=" << sizeof(a)
              << ", address(a)=" << address_a << '\n';

    a = "short";
    b = std::string(1000, 'x');

    std::cout << "after assignment: sizeof(a)=" << sizeof(a)
              << ", address(a)="
              << reinterpret_cast<std::uintptr_t>(&a) << '\n';
    std::cout << "long string: sizeof(b)=" << sizeof(b)
              << ", address(b)="
              << reinterpret_cast<std::uintptr_t>(&b) << '\n';

    return 0;
}
```

Нулевая оптимизация:

```bash

zolars@Arsenys-MacBook-Air 04 % ./3.out

after assignment: sizeof(a)=24, address(a)=6170144144
long string: sizeof(b)=24, address(b)=6170144120
```

Второуровневая отпимизация:

```bash

zolars@Arsenys-MacBook-Air 04 % ./3.out

after assignment: sizeof(a)=24, address(a)=6096760208
long string: sizeof(b)=24, address(b)=6096760184
```

Размер объекта `a` остаётся равным 24 байтам как до, так и после присваивания строки. Его адрес также не меняется. Это объясняется тем, что присваивание изменяет состояние уже существующего объекта `std::string`, а не создаёт новый объект вместо него.

Объект `b` также занимает 24 байта, хотя содержит длинную строку. Это связано с тем, что `sizeof` возвращает размер самого объекта `std::string`, а память для хранения символов может выделяться отдельно.

Во всех трёх примерах результаты показывают, что уровень оптимизации может влиять на расположение объектов в памяти, но не меняет наблюдаемый размер самих типов. Конкретные адреса зависят от запуска программы и условий её выполнения, поэтому по ним нельзя сделать вывод об универсальном порядке размещения переменных во всех программах.
